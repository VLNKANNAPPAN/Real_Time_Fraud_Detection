# ML methodology (design)

The simulator generates users, devices, event times, amounts, merchants, countries, risk interactions, and latent labels with controlled noise. Fraud is not a single feature rule; suspicious legitimate and ordinary-looking fraudulent transactions must exist. Hidden risk variables used to generate labels must never be exposed as training features. Labels are delayed relative to original predictions. Store generation seed/config and a dataset version.

Build offline features by replaying events in their produced arrival order with the exact [`features-v2`](feature-definitions.md) inclusion, window, and lateness rules. The feature snapshot for a transaction is frozen before its event enters history. User aggregates used in training cannot inspect future transactions, later labels, or a final time-sorted table. Synthetic account profile fields must be known as of event time. Only data available at the prediction point may enter model inputs.

Use a chronological train/validation/test split on producer/decision chronology with a documented temporal gap. Synthetic labels arrive one or two days after the transaction; the baseline uses two-day maturation gaps between train and validation, and validation and test. A training label must be available before validation starts; a validation label must be available before test starts. Gap transactions still enter feature history during replay but their labels are not used for training or threshold selection. Compute preprocessing statistics and categorical vocabulary on train only. Choose model and policy thresholds on validation, lock them, and report test metrics once. Where the simulator reuses users, measure performance on both returning and new users if feasible; do not claim that random row splits measure future deployment behavior. Class imbalance is kept realistic, with any class weighting/resampling applied only inside training folds. Start with a scikit-learn `Pipeline`/`ColumnTransformer` and a simple probabilistic baseline such as regularized logistic regression; try a compact tree model only if the baseline shows a concrete limitation.

Report fraud-class precision, recall, F1, PR-AUC, ROC-AUC where both classes exist, confusion matrix, false-positive rate, and false-negative rate. Include prevalence, sample count, and decision costs. Accuracy alone is misleading under imbalance. Inspect score calibration before calling output a probability; use validation-only calibration if needed. A numeric score is still an estimate, not proof of fraud. Pick REVIEW/BLOCK thresholds with explicit false-positive cost and human-review capacity. Operational action metrics are reported separately from model ranking metrics.

Save an immutable model artifact and manifest with artifact hash, model version, ordered input feature names, `feature_version`, exact scikit-learn version, training-frame hash, dataset version, and split policy. The artifact hash suffix makes retrained files distinguishable even within one baseline family. The inference loader validates manifest compatibility before serving. The decision policy is versioned separately and persists alongside the model version actually used. If none ran, persist `inference_status=NOT_RUN` or `FAILED`, null model version and null score. Future delayed labels attach to the original decision; they never alter its original snapshot or score. Drift and production evaluation are distinct from retrospective synthetic test results.
